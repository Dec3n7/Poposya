# Poposya Bot

Discord-бот с модульной гексагональной архитектурой (домен → приложение →
инфраструктура → представление; см. [ARCHITECTURE.md](docs/ARCHITECTURE.md) и
[ТЗ](docs/plans/TZ.md)) плюс **веб-панель** для настройки серверов.

Основные фичи: живая персона Попоси (её голос настраивается пер-сервер) и
отношения на очках (Groq), музыка с YouTube (лайки, радио, караоке), модерация
с апелляциями и кросс-серверными банами, ночные находки, киноклуб, каморки
(временные голосовые), управление ролями, еженедельный дайджест, отслеживание
релизов GitHub и новостей игр Steam в форуме — всё это включается/выключается на
каждом сервере отдельно через панель или команду `/config`.

Проектные документы (ТЗ, планы, архитектурные спеки) собраны в
[docs/plans/](docs/plans/) — там же их актуальный статус.

## Попося: общение и отношения

- **Триггер общения**: упомяните `@Попося` или ответьте реплаем на её сообщение —
  она ответит в характере, с учётом уровня отношений и заметок о вас.
- **Очки**: +1 за каждое адресованное ей сообщение (потолок 20/сутки).
  Роли-статусы выдаются автоматически: ☕ Случайный прохожий (100) → 🌧 Знакомый
  силуэт (250) → 🎨 Занятный собеседник (450) → 🎧 На одной волне (700) →
  🍷 Вечерняя компания (950) → 🖤 Особенный (1200). Титул ✂️👁🖤 Единственный —
  один на сервер, у лидера по очкам (от 1250), переходит при строгом обгоне.
  Пороги и имена ролей настраиваются пер-сервер (панель или `/config`).
- **Роль-новичок** (ступень 0): опциональная роль для тех, кто ещё ниже первого
  порога (0–99 очков) — снимается при взятии первой статус-роли и возвращается при
  угасании. Настройка `relationship_newcomer_role` (имя роли; пусто = выключено).
- **Память**: структурированная заметка о каждом (интересы/характер/темы/чего
  избегать) + резюме последних `AI_DIALOG_SUMMARY_KEEP` (5) диалогов — Попося
  помнит, о чём вы говорили в прошлый раз. Диалог = серия обменов с паузами
  меньше `AI_DIALOG_GAP_MINUTES` (30); долгие разговоры (5+ обменов) копятся
  как «глубина» в `/profile`. После месяца тишины встречает холоднее.
- **Угасание**: после `RELATIONSHIP_DECAY_AFTER_DAYS` (30) дней молчания очки
  тают на `RELATIONSHIP_DECAY_POINTS` (1) каждые `RELATIONSHIP_DECAY_EVERY_DAYS`
  (3) дня; роль снимается тихо, а титул «Единственного» переходит лидеру,
  если держателя обогнали.
- **`/leaderboard`** — топ-10 очков сервера.
- Изредка комментирует включённые треки (шанс и cooldown настраиваются).
- Команды: `/rank` (свои очки и статус), `/relationship points|freeze|sync` (админ).
- **Знакомство**: `/introduce` (админ) публикует представление Попоси и анкету
  с кнопками (пол, сколько внимания, интересы, время года). Ответы попадают
  в промпт; «Не беспокоить» отключает её инициативу к человеку, «Хочу внимания» —
  удваивает шанс комментариев. За заполнение — `SURVEY_BONUS_POINTS` (5) очков разово.
  Кнопки персистентные — работают и после рестарта бота.
- **Секретная комната**: при достижении уровня `SECRET_ROOM_MIN_LEVEL` (5, роль
  «🎧 На одной волне») Попося присылает в ЛС одноразовый ключ. `/secret <ключ>`
  открывает текстовый + голосовой канал на `SECRET_ROOM_HOURS` (12) часов,
  видимый только ролям этого уровня и выше. Комната одна на сервер за раз,
  закрывается автоматически (срок в БД — рестарт не мешает). `/secret` без
  аргумента показывает свой ключ (на случай закрытых ЛС).

## Модерация (права администратора)

| Команда | Описание |
|---|---|
| `/warn user [reason]` | Предупреждение; при `WARN_THRESHOLD` (3) — автомут на `WARN_MUTE_MINUTES` мин и сброс |
| `/warnings user` | Все предупреждения пользователя |
| `/clearwarns user` | Сбросить предупреждения |
| `/modhistory user` | Полная история модерации по участнику (варны, муты, баны, кики) |
| `/mute user minutes [reason]` | Мут (native timeout — снимается сам, рестарт бота не влияет) |
| `/unmute user` | Досрочно снять мут |
| `/kick user [reason]` | Выгнать участника с сервера |
| `/ban user [reason]` | Забанить навсегда |
| `/tempban user minutes reason` | Временный бан; разбан автоматический, сроки в БД переживают рестарт |
| `/unban user_id` | Досрочный разбан по ID |
| `/bans` | Активные временные баны |
| `/clear amount` | Удалить 1–100 сообщений в канале |
| `/slowmode seconds` | Slowmode 0–21600 c (0 = выкл) |
| `/rage user` | Попося в ярости: перебрасывает по войсам и кикает с сервера |
| `/say text [channel]` | Написать от лица бота |
| `/checkuser user` | [модер] Забанен ли участник на других серверах, где стоит бот (эфемерно) |

**Антиспам**: `SPAM_LIMIT` сообщений за `SPAM_WINDOW` секунд — первый раз
предупреждение, повторно (в течение часа) — мут на `SPAM_MUTE_MINUTES` минут.
Все действия модерации дублируются в `LOG_CHANNEL` (ID канала, 0 = выкл).

**Апелляции**: при бане/темпбане/муте наказанному приходит в ЛС кнопка
«Обжаловать» → форма → апелляция уходит в `appeals_channel` с кнопками
Принять/Отклонить. «Принять» само снимает наказание (разбан/анмут) и шлёт ЛС
участнику. Кнопки персистентные (переживают рестарт). Модуль — `appeals`.

**Кросс-серверные баны**: бот собирает баны со всех серверов, где стоит, и даёт
модератору увидеть, что участник забанен где-то ещё — через `/checkuser` или
вкладку «Модерация» в панели. Наружу в Discord ничего не постится. Сбор идёт
глобально; per-server тумблер `banwatch` гасит только показ на конкретном сервере.

## Автоматические события

- **Приветствие/прощание** — в `WELCOME_CHANNEL`; новичку выдаётся роль
  `AUTO_ROLE` (пусто = выключено). Возвращение после `ABSENT_DAYS_THRESHOLD`
  дней Попося отмечает репликой.
- **Настроение 0–100** — внутренний счётчик, влияет на тон AI-ответов:
  +2 активность в `MAIN_CHANNEL`, +1 ответ на упоминание, −5 оскорбление бота
  (список слов `BOT_INSULT_WORDS`), дрейф к 20 при тишине >2 ч и к 75 при активности.
- **Альбом Попоси** — сообщение, набравшее `ALBUM_REACTION_THRESHOLD` (5) реакций
  одним эмодзи, пересылается в канал `ALBUM_CHANNEL` с её кураторской подписью.
  `ALBUM_REACTION_EMOJI` ограничивает подсчёт конкретным эмодзи (пусто = любое).
  Каждое сообщение попадает в альбом один раз (дедупликация в БД).
- **Праздники** (`HOLIDAYS`, дефолт: Новый год, 14 февраля, Хэллоуин, Рождество):
  объявление в `MAIN_CHANNEL`, приподнятое настроение и очки
  ×`HOLIDAY_POINTS_MULTIPLIER` (2) весь день (потолок тоже удваивается).
- **«Скучаю»** после `LONELY_HOURS` часов тишины в `MAIN_CHANNEL` (нужен Groq).
- **Случайные мысли** раз в `RANDOM_THOUGHT_MIN_HOURS`–`RANDOM_THOUGHT_MAX_HOURS`
  часов — только если в канале была активность за последний час.

## Логирование

Консоль — уровень `LOG_LEVEL` (формат `LOG_FORMAT`: plain/json); файл
`LOG_FILE` (по умолчанию `logs/bot.log`) — всегда DEBUG, ротация 5 МБ × 3.

**Логи в Discord-канал**: `DISCORD_LOG_CHANNEL` (ID канала, 0 = выключено) +
`DISCORD_LOG_LEVEL` (DEBUG/INFO/WARNING/ERROR). На лету — команда
`/botlog level [channel]` (админ): смена уровня, канала или OFF; действует
до рестарта, постоянные значения — в `.env`. Записи шлются пачками раз в
5 секунд; логи самого discord.py исключены (иначе отправка порождала бы
бесконечную петлю).

**Важно для Discord Developer Portal:**
1. Включите **Message Content Intent** (Bot → Privileged Gateway Intents) — без
   него бот не видит текст сообщений и общение не работает.
2. Включите **Server Members Intent** (там же) — для приветствий и прощаний.
3. Боту нужны права **Manage Roles** (роль выше ролей-статусов) и
   **Timeout Members** (Moderate Members) для антиспама и варнов.

**Groq**: бесплатный ключ на https://console.groq.com/keys → `GROQ_API_KEY` в `.env`.
Без ключа бот работает (музыка, очки, роли), отключается только генерация реплик.

**Надёжность AI**: запросы ретраятся с backoff (уважая `Retry-After`), при отказе
основной модели реплику пишет резервная (`AI_FALLBACK_MODEL`), а серия сбоев
размыкает circuit breaker (`AI_CB_*`) — бот мгновенно отвечает заготовкой в
характере вместо зависания, пока провайдер не оживёт.

## Возможности музыкального модуля

- `/play <ссылка или запрос>` — YouTube-видео/плейлист играет сразу, текстовый
  запрос показывает 5 результатов с выбором. **Spotify-ссылки на треки** тоже
  работают (название через oEmbed → поиск на YouTube, ключи не нужны).
  **Плейлисты и альбомы Spotify** — если заданы `SPOTIFY_CLIENT_ID/SECRET`: бот
  берёт список треков через Spotify Web API и ищет каждый на YouTube (до
  `MUSIC_PLAYLIST_LIMIT` штук), сообщая, сколько из скольких нашлось. Без ключей
  плейлисты недоступны, треки работают.
- `/playnext <ссылка или запрос>` — то же, но трек встаёт первым в очереди.
- Сообщение-плеер с кнопками: ⏮️ назад · ⏯️ пауза/играть · ⏭️ следующий ·
  🔁 повтор (выкл/трек/все) · ⏹️ стоп · 🔉/🔊 громкость · 🔀 перемешать ·
  📜 караоке · ❤️ лайк (в личную коллекцию) · 💾 сохранить очередь в плейлист.
  Караоке-текст подгружается в кэш при старте трека — включается мгновенно;
  повторное нажатие выключает; если синхронного текста нет — покажет обычный.
- Живой прогресс трека (полоса + `1:23 / 3:45`) через редактирование сообщения.
- `/queue`, `/skip`, `/shuffle`, `/remove <номер>`, `/seek <1:23 / 83 / 1:02:03>`,
  `/history` (недавние треки — сыграть снова), `/stop`, `/pause`, `/resume`,
  `/volume 0–200`, `/nowplaying`, `/leave`.
- `/lyrics` — текст текущего трека (lrclib.net, включая японскую и русскую музыку);
  `/lyrics live:true` — караоке-режим: текст абзацами синхронно с воспроизведением
  (сообщение обновляется при смене абзаца, следующий абзац показан приглушённо).
- **Плейлисты сервера**: `/playlist save|play|list|delete` — сохранение текущей
  очереди в БД (лимиты `MUSIC_PLAYLIST_MAX_PER_GUILD`/`MAX_TRACKS`); удаляет
  автор или админ.
- **Лайки треков**: ❤️ на плеере кладёт трек в личную коллекцию. `/liked
  list|play|all|remove|save` — свои (или чужие) лайки: посмотреть, включить,
  добавить все в очередь, убрать, сохранить как плейлист сервера.
- **Совместимость вкусов**: `/taste [user]` — насколько сходятся музыкальные
  вкусы (по пересечению лайков).
- **📻 Радио**: очередь опустела — Попося сама подхватывает треки из лайков
  слушателей в канале, чтобы музыка не обрывалась (состояние переживает
  пересоздание плеера; гаснет при стопе/выходе).
- **Кэш аудио против заиканий**: следующие `MUSIC_PREFETCH_TRACKS` (3) трека
  очереди фоном скачиваются на диск (`MUSIC_CACHE_DIR`, LRU-лимит
  `MUSIC_CACHE_MAX_MB` МБ) и играют из файла — сеть не влияет на звук.
  Первый трек стартует мгновенно стримом; если скачать не удалось — стрим
  как фолбэк. Live-эфиры всегда стримятся. `MUSIC_PREFETCH_TRACKS=0` — выкл.
- Авто-выход: когда очередь кончилась, плеер сразу удаляется; за
  `MUSIC_IDLE_WARN_SECONDS` (2 мин) до выхода Попося спрашивает «включить
  что-то ещё?», и если ответа нет — уходит через `MUSIC_IDLE_TIMEOUT` (5 мин)
  после конца музыки. Новый трек всегда создаёт свежий плеер внизу канала.
  Также выходит сразу, когда все покинули канал.
- Кнопки работают только для тех, кто в голосовом канале с ботом.

## Каморки: временные голосовые каналы

Зашёл в канал-хаб — Попося создаёт личную «каморку» и переносит туда. Вышел
последний человек — канал исчезает вместе со всей перепиской. Команд у модуля
нет вообще: всё делается кнопками.

**Включение** (админ): `/config channel key:tempvoice_hub_channel channel:#хаб`.
Хаб — он же выключатель: не задан, значит модуль молчит.

**Панель** из восьми кнопок лежит в двух местах и переживает рестарт бота:

- постоянная **витрина в чате хаба** — действует на ту каморку, где ты сейчас
  сидишь, состояние показывает лично тебе (сообщение одно на всех, поэтому
  чужую дверь в нём не покажешь);
- личная **панель в чате самой каморки** — там же видно её состояние: дверь,
  видимость, мест, хозяин. Discord открывает этот чат сам, когда заходишь в
  канал, так что панель попадается на глаза без единого клика.

| Кнопка | Что делает |
|---|---|
| 🔒 **Замок** | Закрыть/открыть дверь для всех |
| 🙈 **Скрыть** | Убрать/вернуть канал из списка |
| ✏️ **Имя** | Переименовать (Discord разрешает 2 раза за 10 минут — на третий Попося честно скажет, сколько ждать) |
| 🔢 **Мест** | Лимит 0–99; 0 = без лимита |
| 👢 **Выгнать** | Выставить из канала (пикер участника) |
| ✅ **Впустить** | Пускать конкретного человека даже в закрытую |
| ⛔ **Забанить** | Закрыть дверь и выставить, если уже внутри |
| 👑 **Забрать** | Единственная кнопка не для владельца: хозяин ушёл, а ты внутри — каморка твоя. При живом хозяине не сработает |

Всё, кроме «Забрать», доступно только владельцу. Блок-листы отдельно не
хранятся — это обычные права канала Discord, поэтому исчезают вместе с ним.

Время в каморках идёт в очки отношений наравне с любым другим войсом.
Осиротевшие каморки (пустые или удалённые руками, пока бот лежал) убираются при
старте — реестр каналов в БД.

| Настройка `/config` | Что делает |
|---|---|
| `tempvoice_hub_channel` | Канал-хаб; 0 = модуль выключен |
| `tempvoice_category` | Категория для каморок; 0 = категория хаба |
| `tempvoice_max_per_guild` | Потолок каморок, 1–50 (у Discord жёсткий лимит: 50 каналов в категории) |
| `tempvoice_default_limit` | Мест в новой каморке, 0–99; 0 = без лимита |

Боту нужны **Manage Channels** (создавать и удалять) и **Move Members**
(перенести в каморку) — без второго человек останется сидеть в хабе.

## Ночные находки Попоси

Попося иногда «выходит на ночную прогулку по Токио» и находит редкий предмет —
анонс с кнопкой **«Сходить туда»** появляется в канале находок. Забрать может
первый успевший; предмет попадает в личную коллекцию, а за находку начисляются
очки отношений (у редких находок — больше). Кнопка персистентная (переживает
рестарт), находка «протухает», если её не забрали вовремя.

| Команда | Описание |
|---|---|
| `/finds` | Активная находка на сервере сейчас |
| `/collection` | Твоя коллекция найденного (по редкости) |
| `/gift item` | Подарить предмет Попосе — она запоминает, даёт бонус очков |
| `/walk` | Попросить особую прогулку за очки (раз в неделю, кулдаун) |

Интервал спавна, канал и лимиты настраиваются на сервере (`/config`): хорошее
настроение Попоси и праздники повышают шанс и качество находок.

## Киноклуб

Совместный просмотр фильмов с голосованием и оценками. Ведущий предлагает фильмы
в вотчлист, запускает киновечер (опрос по топу вотчлиста → победитель → сеанс),
а после просмотра открывается сбор оценок 1–10 с отзывами. Итоги и все рецензии
уезжают в форум «золотой фонд», в канале остаётся указатель. Попося тоже смотрит
и ставит свой вердикт («N/10 — колкая рецензия»).

| Команда | Описание |
|---|---|
| `/movie add|list|remove|top|watched` | Вотчлист: добавить/список/убрать/топ/просмотренные |
| `/movienight start|cancel` | Запустить или отменить киновечер (опрос + сеанс) |

Канал киноклуба и форум золотого фонда задаются на сервере через `/config` или
на вкладке «Киноклуб» веб-панели.

## GitHub-репозитории

`/git add owner/name` подписывает репозиторий GitHub: бот заводит по нему тред в
форум-канале и постит туда каждый новый релиз — заголовок, тег и текст release
notes. При добавлении сразу показывается текущий последний релиз; дальше опрос
идёт фоном (по умолчанию раз в 2 часа).

| Команда (админ) | Описание |
|---|---|
| `/git add <owner/name или ссылка>` | Отслеживать релизы репозитория |
| `/git list` | Отслеживаемые репозитории сервера |
| `/git remove <owner/name>` | Перестать отслеживать |

Форум-канал задаётся на сервере: настройка `git_forum_channel` (`/config` или
вкладка «Настройки» → «GitHub-репозитории»). Токен не обязателен — без него бот
работает анонимно (лимит GitHub 60 запросов/час на IP; при 2-часовом опросе
хватает на десятки репозиториев). `GITHUB_TOKEN` в `.env` поднимает лимит до
5000/ч. Интервал — `GITHUB_POLL_INTERVAL_MINUTES` (120).

## Steam-игры

`/steam add <AppID>` подписывает игру Steam: бот заводит по ней тред в форум-канале
и постит туда официальные новости — обновления, патчи, анонсы — с картинкой и
текстом (Steam-разметка переводится в оформление Discord). Внешние статьи прессы,
которые Steam подмешивает в ленту игры, отсекаются. При добавлении сразу
показывается последняя новость; дальше опрос — раз в 2 часа.

| Команда (админ) | Описание |
|---|---|
| `/steam add <AppID или ссылка на магазин>` | Отслеживать новости игры |
| `/steam list` | Отслеживаемые игры сервера |
| `/steam remove <AppID>` | Перестать отслеживать |

Форум-канал — настройка `steam_forum_channel` (`/config` или вкладка «Настройки» →
«Steam-игры»). Ключ Steam **не нужен**: новости берутся официальным API
`GetNewsForApp`. AppID — число из адреса страницы игры
(`store.steampowered.com/app/<AppID>/...`). Интервал —
`STEAM_POLL_INTERVAL_MINUTES` (120).

## Дайджест недели

Раз в неделю (воскресенье ~17:00 UTC ≈ 20:00 МСК) Попося постит в `digest_channel`
итоги недели голосом персоны: активность, новые лица, заметные события. Собирается
через AI; при сбое провайдера — шаблонный текст без ИИ. `/digest` (админ) публикует
дайджест вручную прямо сейчас. Дедуп по ISO-неделе. Модуль — `digest` (канал в
`/config` или на вкладке «Настройки»).

## Управление ролями

Роли сервера отражаются («зеркалятся») в БД из событий Discord — их иерархия,
цвета, права и число носителей. Управление идёт **через веб-панель** (вкладка
«Роли»): создание/переименование/цвет (с пресетами палитры), перестановка
порядка, права по каталогу, удаление, массовая выдача/снятие и роли конкретного
участника, а также шаблоны ролей (встроенные и свои), экспорт/импорт и
автовыдача ролей новичкам при входе. Панель
пишет команду в мост, а реальный вызов Discord делает бот — с проверкой границы
(бот трогает только роли ниже своей высшей и не managed/@everyone) и аудитом
каждого действия. Наглядные виджеты: пончик распределения ролей, чипы, редактор
прав с гашением недоступных боту тумблеров.

## Пер-серверные настройки и модули

Все настройки и включение/выключение модулей — **отдельно для каждого сервера**.
Управлять можно двумя способами:

- **Команда `/config`** (админ): `show` (текущие значения), `channel`
  (настройки-каналы: хаб каморок, канал находок, форум киноклуба и т.д.),
  `toggle` (булевы флаги), `number` (числовые пороги), `limits` (лимиты ролей),
  `reset` (вернуть пороги/имена ролей к глобальным дефолтам). У ключей —
  автодополнение.
- **Веб-панель**: вкладки «Настройки» (значения) и «Модули» (мастер-тумблеры).

Мастер-тумблеры модулей (каждый — per-server, дефолт «вкл», кроме staykick):
`ai_chat` (+подфлаг `ai_passive`), `relationship`, `activity`, `moderation`,
`music`, `cinema`, `finds`, `git`, `steam`, `tempvoice`, `fun`, `introduce`,
`secret_room`, `digest`, `appeals`, `banwatch`, `staykick`. Выключенный модуль
молчит на этом сервере: команды отвечают «модуль выключен», фоновые события не
запускаются. (`banwatch` — тумблер гасит только показ; сбор банов глобален.)

## Веб-панель

Отдельный фронт (React + TypeScript + Vite, `web/`) и API (FastAPI,
`src/api/`) поверх той же БД и той же бизнес-логики, что у бота — без дублирования
правил. Вход по **Discord OAuth**: видно только серверы, где ты вправе управлять
(Manage Guild/Administrator) **и** где стоит бот; сессия — в подписанной куке.

Вкладки панели: **Обзор** (сводка сервера), **Люди**, **Роли**, **Киноклуб**,
**Музыка** (live-состояние плеера), **Находки**, **Модерация** (в т.ч. баны с
других серверов), **Апелляции**, **Журнал** (аудит действий), **Модули**
(тумблеры), **Настройки** (значения, в т.ч. форум-каналы GitHub и Steam),
**Персона** (редактирование голоса и фраз Попоси для сервера — библиотека, из
которой она говорит) и **WARDEN** (режим и инциденты сторожа, пауза рестартов).

Действия, меняющие Discord (роли, модерация, музыка), панель не делает напрямую —
она пишет команду в мост (таблица команд + `pg_notify`), а исполняет её бот, и
результат/ошибка возвращаются обратно. Поэтому панель поднимается вместе с
Postgres (профиль `postgres` в `docker-compose.yml`, см. ниже): сервисы `api`
(uvicorn) и `web` (nginx раздаёт статику и проксирует `/api` — один origin, без
CORS, кука работает).

## Приватность и данные

- **`/forgetme`** — участник стирает свои личные данные на текущем сервере
  (очки, заметки, память, коллекция, лайки и т.п.) с подтверждением. Записи
  модерации при этом сохраняются.
- **Автоочистка при выходе бота** — когда бота убирают с сервера, данные этого
  сервера стираются фоновым циклом по истечении окна отсрочки (защита от
  случайного кика/переинвайта); возврат бота отменяет удаление.
- Правовые документы (условия использования и политика конфиденциальности) —
  проект `poposya-legal` (отдельный статический сайт).

## Установка через Docker — пошаговая инструкция

Подходит тем, кто ничего не знает о Python: всё нужное (Python, FFmpeg, opus)
уже внутри образа. Нужен только Docker.

### Шаг 1. Установите Docker Desktop

1. Скачайте с https://www.docker.com/products/docker-desktop/ и установите.
   На Windows при установке согласитесь на включение **WSL 2** и перезагрузите ПК.
2. Запустите Docker Desktop и дождитесь статуса «Engine running».
3. Проверка в терминале: `docker --version` — должна показаться версия.

### Шаг 2. Создайте бота в Discord

1. https://discord.com/developers/applications → **New Application** → имя (например, Poposya).
2. Вкладка **Bot** → **Reset Token** → скопируйте токен (никому не показывайте).
3. Там же включите **Message Content Intent** и **Server Members Intent**
   (Privileged Gateway Intents) — оба обязательны.
4. Вкладка **OAuth2** → скопируйте **Client ID** и пригласите бота на сервер ссылкой
   (подставьте свой CLIENT_ID):
   `https://discord.com/oauth2/authorize?client_id=CLIENT_ID&scope=bot%20applications.commands&permissions=1099833617430`
5. На сервере поднимите роль бота **выше** будущих ролей-статусов
   (Настройки сервера → Роли → перетащите роль бота вверх).

### Шаг 3. Получите ключ Groq (бесплатно)

https://console.groq.com/keys → **Create API Key** → скопируйте ключ.

### Шаг 4. Настройте проект

В папке проекта скопируйте `.env.example` в файл с именем `.env` и заполните:

```dotenv
DISCORD_TOKEN=токен_из_шага_2
GROQ_API_KEY=ключ_из_шага_3
DEV_GUILD_ID=id_вашего_сервера          # чтобы команды появились сразу
```

(путь к базе для контейнера подставляется автоматически в docker-compose.yml —
править `DATABASE_URL` не нужно)

(ID сервера: в Discord включите «Режим разработчика» в настройках → ПКМ по серверу → «Копировать ID».)

### Шаг 5. Запустите

В терминале, в папке проекта:

```powershell
docker compose up -d --build
```

Первая сборка занимает несколько минут. Проверки:

- `docker compose ps` — у сервиса `bot` статус должен стать **healthy** (после ~минуты);
- http://localhost:8080/health в браузере — `{"status": "healthy", ...}`;
- логи: `docker compose logs -f bot`;
- в Discord появились команды `/play`, `/rank` и бот отвечает на упоминание.

### Управление

| Действие | Команда |
|---|---|
| Остановить | `docker compose down` (база сохраняется на volume) |
| Перезапустить | `docker compose restart bot` |
| Обновить после изменения кода/настроек | `docker compose up -d --build` |
| Логи | `docker compose logs -f bot` |

### Если музыка не играет (ошибка про «Sign in to confirm»)

YouTube требует cookies (см. раздел выше). Для Docker: экспортируйте `cookies.txt`
расширением браузера, положите файл рядом с `docker-compose.yml`, раскомментируйте
строку `./cookies.txt:...` в compose-файле и добавьте в `.env`:
`YTDLP_COOKIES_FILE=/app/data/cookies.txt`. Вариант `YTDLP_COOKIES_FROM_BROWSER`
в контейнере не работает — браузера там нет.

### Health-эндпоинты

Бот поднимает HTTP-сервер на порту 8080 (настройка `HEALTH_PORT`): `/health` и
`/ready` возвращают состояние проверок `database` и `discord` (200 — всё живо,
503 — что-то упало). Docker сам перезапустит контейнер по healthcheck из compose.

### PostgreSQL и веб-панель

**В Docker БД — всегда PostgreSQL.** Сервисы `db`, `api` и `web` описаны в
`docker-compose.yml` и поднимаются вместе с ботом. SQLite остаётся только для
локального запуска без Docker и для тестов (код переносим: весь набор тестов
проходит и против PostgreSQL 16 без единой правки). **Веб-панели PostgreSQL
обязателен**: командный мост между панелью и ботом использует `LISTEN/NOTIFY`,
поэтому панель и бот делят одну базу.

Задайте в `.env` пароль базы и адрес подключения (обязательны для Docker):

```dotenv
POSTGRES_PASSWORD=придумайте_пароль
BOT_DATABASE_URL=postgresql+asyncpg://poposya:придумайте_пароль@db:5432/poposya
```

Для входа в панель нужны Discord OAuth-креды (вкладка OAuth2 в Developer Portal;
в Redirects добавьте `http://localhost:8081/api/auth/callback`):

```dotenv
DISCORD_CLIENT_ID=client_id_приложения
DISCORD_CLIENT_SECRET=client_secret_приложения
WEB_SESSION_SECRET=длинная_случайная_строка   # подпись сессионной куки
WEB_OAUTH_REDIRECT=http://localhost:8081/api/auth/callback
WEB_ALLOWED_ORIGIN=http://localhost:8081
```

Затем запускайте весь стек:

```powershell
docker compose up -d --build
```

Поднимутся `bot`, `db`, `api` (uvicorn) и `web` (nginx). Панель откроется на
**https://localhost:8443** — вход через Discord, дальше видны только серверы, где
вы вправе управлять и где стоит бот.

`BOT_DATABASE_URL` — отдельная переменная, а не `DATABASE_URL`: последняя в
`.env` рассчитана на запуск без Docker и подменила бы адрес контейнерной базы.
Обе переменные обязательны: без них `docker compose` падает на разборе файла —
защита от тихого старта на пустом SQLite (раньше забытый флаг уводил бота на
пустую базу и стоил данных).

**Данные сами не переедут** — новая база будет пустой. Для переноса из
локальной SQLite в PostgreSQL есть встроенный скрипт: сначала поднимите схему в
Postgres (старт бота с `AUTO_MIGRATE` или `alembic upgrade head`), остановите
бота, затем

```powershell
python -m src.infrastructure.db.migrate_sqlite_to_pg `
    --source ./poposya.db `
    --dest "postgresql+asyncpg://poposya:ПАРОЛЬ@localhost:5432/poposya"
```

Он копирует все таблицы в порядке зависимостей, конвертирует типы (boolean,
даты) по описанию моделей и подтягивает sequence'ы, чтобы следующая запись бота
не столкнулась с занятым id. Схему не создаёт (это делает Alembic) и по
умолчанию требует пустую целевую базу — защита от вставки в живые данные
(`--force` чтобы дописать поверх).

**Бэкапы работают и на PostgreSQL**: при старте и раз в `BACKUP_INTERVAL_HOURS`
(24) бот делает `pg_dump -Fc` и хранит `BACKUP_KEEP` (7) последних. Дампы лежат
в `BACKUP_DIR` (`data/backups`, в Docker это volume `bot_data` — **отдельный от
тома БД `pg_data`**, поэтому переживают её потерю). Восстановление:
`pg_restore -d <база> poposya-<дата>.dump`. Отключить — `BACKUP_INTERVAL_HOURS=0`
или `BACKUP_KEEP=0`; тогда бот предупредит об отсутствии копий в логе старта.

### Если YouTube пишет «Sign in to confirm you're not a bot»

YouTube помечает некоторые IP и требует авторизацию — без cookies поток не отдаётся
(поиск при этом работает). Решение:

1. Установите в браузер расширение **Get cookies.txt LOCALLY**.
2. Зайдите на youtube.com под своим аккаунтом и экспортируйте cookies в файл.
3. В `.env` укажите: `YTDLP_COOKIES_FILE=C:/путь/к/cookies.txt`.

Вариант `YTDLP_COOKIES_FROM_BROWSER=chrome` работает только когда Chrome закрыт
(база cookies залочена запущенным браузером), поэтому файл надёжнее.

## Структура

Гексагональная слоёная архитектура: каждая фича — своя вертикаль
`domain/ → application/ → cog`, изолированная от других (связь только через
`IEventBus`). Веб-панель (`src/api` + `web/`) стоит поверх той же
`application/`-логики — без дублирования правил.

```
src/
├── domain/            # сущности и доменные события — без фреймворков
│   ├── events/        # DomainEvent / CriticalDomainEvent, IEventBus
│   └── <фича>/        # music, relationship, roles, cinema, finds, moderation,
│                      # tempvoice, activity, ai_chat, staykick, repos (/git),
│                      # steam (/steam), persona, metrics, audit…
├── application/       # логика фич и порты (по подпапке на фичу)
│   ├── interfaces/    # IAudioSource, IVoiceConnection, IUnitOfWork
│   ├── guild_config/  # пер-серверные настройки (get/set/валидация)
│   ├── roles/         # зеркало ролей + use-cases управления
│   └── di/            # root_container — composition root
├── infrastructure/    # реализации портов
│   ├── audio/         # yt-dlp
│   ├── github/        # клиент GitHub API (релизы для /git)
│   ├── steam/         # клиент Steam API + BBCode→Discord (новости для /steam)
│   ├── discord/       # клиент, голосовой адаптер, коги (cogs/*)
│   │   └── cogs/music/  # тонкий ког + сервисы: session, service (плеер/idle),
│   │                    # lyrics (караоке), radio, views, formatting
│   ├── commands/      # командный мост панель→бот (LISTEN/NOTIFY + слушатель)
│   ├── db/            # SQLAlchemy: models, repositories, migrations, backup,
│   │                  # migrate_sqlite_to_pg (перенос данных SQLite→Postgres)
│   ├── events/        # InMemoryEventBus (изоляция ошибок подписчиков)
│   └── logging/       # JSON-логи, correlation_id (contextvars)
├── api/               # FastAPI веб-панель: routers/*, OAuth, сессии, аудит
├── config.py          # Settings (pydantic-settings, .env)
└── main.py            # точка входа бота  (панель — src/api/main.py)

web/                   # фронт панели: React + TypeScript + Vite (nginx в Docker)
docs/plans/            # ТЗ, планы и архитектурные спеки (со статусом)
```

Новая фича добавляется по алгоритму раздела 14 [ТЗ](docs/plans/TZ.md): своя
подпапка в `domain/`, `application/`, свой ког — существующие фичи не правятся,
связь только через события `IEventBus`. Правила и запреты слоёв — в
[ARCHITECTURE.md](docs/ARCHITECTURE.md) и [AI_RULES.md](docs/AI_RULES.md).
