# Poposya Bot

Discord-бот с модульной гексагональной архитектурой (см. [ТЗ](ТЗ_Discord_бот_v2_3.md)).
Фичи: музыка с YouTube, система отношений на очках, общение персоны Попоси (Groq).

## Попося: общение и отношения

- **Триггер общения**: упомяните `@Попося` или ответьте реплаем на её сообщение —
  она ответит в характере, с учётом уровня отношений и заметок о вас.
- **Очки**: +1 за каждое адресованное ей сообщение (потолок 20/сутки).
  Роли-статусы выдаются автоматически: ☕ Случайный прохожий (50) → 🌧 Знакомый
  силуэт (100) → 🎨 Занятный собеседник (150) → 🎧 На одной волне (200) →
  🍷 Вечерняя компания (250) → 🖤 Особенный (300). Титул ✂️👁🖤 Единственный —
  один на сервер, у лидера по очкам (от 350), переходит при строгом обгоне.
- **Память**: структурированная заметка о каждом (интересы/характер/темы/чего
  избегать) + резюме последних `AI_DIALOG_SUMMARY_KEEP` (5) диалогов — Попося
  помнит, о чём вы говорили в прошлый раз. Диалог = серия обменов с паузами
  меньше `AI_DIALOG_GAP_MINUTES` (30); долгие разговоры (5+ обменов) копятся
  как «глубина» в `/profile`. После месяца тишины встречает холоднее.
- **Угасание**: после `RELATIONSHIP_DECAY_AFTER_DAYS` (30) дней молчания очки
  тают на `RELATIONSHIP_DECAY_POINTS` (1) каждые `RELATIONSHIP_DECAY_EVERY_DAYS`
  (3) дня; роль снимается тихо, а титул «Единственного» переходит лидеру,
  если держателя обогнали.
- **`/leaderboard`** — топ-10 очков сервера.
- Изредка комментирует включённые треки (шанс и cooldown настраиваются).
- Команды: `/rank` (свои очки и статус), `/relationship points|freeze|sync` (админ).
- **Знакомство**: `/introduce` (админ) публикует представление Попоси и анкету
  с кнопками (пол, сколько внимания, интересы, время года). Ответы попадают
  в промпт; «Не беспокоить» отключает её инициативу к человеку, «Хочу внимания» —
  удваивает шанс комментариев. За заполнение — `SURVEY_BONUS_POINTS` (5) очков разово.
  Кнопки персистентные — работают и после рестарта бота.
- **Секретная комната**: при достижении уровня `SECRET_ROOM_MIN_LEVEL` (5, роль
  «🎧 На одной волне») Попося присылает в ЛС одноразовый ключ. `/secret <ключ>`
  открывает текстовый + голосовой канал на `SECRET_ROOM_HOURS` (12) часов,
  видимый только ролям этого уровня и выше. Комната одна на сервер за раз,
  закрывается автоматически (срок в БД — рестарт не мешает). `/secret` без
  аргумента показывает свой ключ (на случай закрытых ЛС).

## Модерация (права администратора)

| Команда | Описание |
|---|---|
| `/warn user [reason]` | Предупреждение; при `WARN_THRESHOLD` (3) — автомут на `WARN_MUTE_MINUTES` мин и сброс |
| `/warnings user` | Все предупреждения пользователя |
| `/clearwarns user` | Сбросить предупреждения |
| `/mute user minutes [reason]` | Мут (native timeout — снимается сам, рестарт бота не влияет) |
| `/unmute user` | Досрочно снять мут |
| `/tempban user minutes reason` | Временный бан; разбан автоматический, сроки в БД переживают рестарт |
| `/unban user_id` | Досрочный разбан по ID |
| `/bans` | Активные временные баны |
| `/clear amount` | Удалить 1–100 сообщений в канале |
| `/slowmode seconds` | Slowmode 0–21600 c (0 = выкл) |
| `/rage user` | Попося в ярости: перебрасывает по войсам и кикает с сервера |
| `/say text [channel]` | Написать от лица бота |

**Антиспам**: `SPAM_LIMIT` сообщений за `SPAM_WINDOW` секунд — первый раз
предупреждение, повторно (в течение часа) — мут на `SPAM_MUTE_MINUTES` минут.
Все действия модерации дублируются в `LOG_CHANNEL` (ID канала, 0 = выкл).

## Развлечения и утилиты

| Команда | Описание |
|---|---|
| `/roll [sides]` | Кубик (по умолчанию d6) |
| `/coinflip` | Монетка |
| `/topic` | Случайная тема для разговора |
| `/profile [user]` | Карточка от лица Попоси: привязанность с прогресс-баром, активность, «что я знаю о тебе» (её заметки), отношение, ДР, отметки-достижения. Обращение и футер меняются с уровнем |
| `/birthday day month` | Свой день рождения без года; за `BIRTHDAY_REMIND_DAYS` (3) дня — напоминание в `MAIN_CHANNEL`, в сам день — поздравление |
| `/rules` | Правила сервера (пока тестовый текст) |
| `/serverstats` | Статистика сервера |
| `/remind minutes text` | Напоминание в ЛС; хранится в БД, переживает рестарт |
| `/send user text [mode]` | Доставка сообщения через Попосю в ЛС: открыто или анонимно. Анонимность — только для получателя: в `LOG_CHANNEL` всегда пишется реальный отправитель. Лимит `SEND_PER_HOUR` (5) в час |

## Автоматические события

- **Приветствие/прощание** — в `WELCOME_CHANNEL`; новичку выдаётся роль
  `AUTO_ROLE` (пусто = выключено). Возвращение после `ABSENT_DAYS_THRESHOLD`
  дней Попося отмечает репликой.
- **Настроение 0–100** — внутренний счётчик, влияет на тон AI-ответов:
  +2 активность в `MAIN_CHANNEL`, +1 ответ на упоминание, −5 оскорбление бота
  (список слов `BOT_INSULT_WORDS`), дрейф к 20 при тишине >2 ч и к 75 при активности.
- **Альбом Попоси** — сообщение, набравшее `ALBUM_REACTION_THRESHOLD` (5) реакций
  одним эмодзи, пересылается в канал `ALBUM_CHANNEL` с её кураторской подписью.
  `ALBUM_REACTION_EMOJI` ограничивает подсчёт конкретным эмодзи (пусто = любое).
  Каждое сообщение попадает в альбом один раз (дедупликация в БД).
- **Праздники** (`HOLIDAYS`, дефолт: Новый год, 14 февраля, Хэллоуин, Рождество):
  объявление в `MAIN_CHANNEL`, приподнятое настроение и очки
  ×`HOLIDAY_POINTS_MULTIPLIER` (2) весь день (потолок тоже удваивается).
- **«Скучаю»** после `LONELY_HOURS` часов тишины в `MAIN_CHANNEL` (нужен Groq).
- **Случайные мысли** раз в `RANDOM_THOUGHT_MIN_HOURS`–`RANDOM_THOUGHT_MAX_HOURS`
  часов — только если в канале была активность за последний час.

## Логирование

Консоль — уровень `LOG_LEVEL` (формат `LOG_FORMAT`: plain/json); файл
`LOG_FILE` (по умолчанию `logs/bot.log`) — всегда DEBUG, ротация 5 МБ × 3.

**Логи в Discord-канал**: `DISCORD_LOG_CHANNEL` (ID канала, 0 = выключено) +
`DISCORD_LOG_LEVEL` (DEBUG/INFO/WARNING/ERROR). На лету — команда
`/botlog level [channel]` (админ): смена уровня, канала или OFF; действует
до рестарта, постоянные значения — в `.env`. Записи шлются пачками раз в
5 секунд; логи самого discord.py исключены (иначе отправка порождала бы
бесконечную петлю).

**Важно для Discord Developer Portal:**
1. Включите **Message Content Intent** (Bot → Privileged Gateway Intents) — без
   него бот не видит текст сообщений и общение не работает.
2. Включите **Server Members Intent** (там же) — для приветствий и прощаний.
3. Боту нужны права **Manage Roles** (роль выше ролей-статусов) и
   **Timeout Members** (Moderate Members) для антиспама и варнов.

**Groq**: бесплатный ключ на https://console.groq.com/keys → `GROQ_API_KEY` в `.env`.
Без ключа бот работает (музыка, очки, роли), отключается только генерация реплик.

**Надёжность AI**: запросы ретраятся с backoff (уважая `Retry-After`), при отказе
основной модели реплику пишет резервная (`AI_FALLBACK_MODEL`), а серия сбоев
размыкает circuit breaker (`AI_CB_*`) — бот мгновенно отвечает заготовкой в
характере вместо зависания, пока провайдер не оживёт.

## Возможности музыкального модуля

- `/play <ссылка или запрос>` — YouTube-видео/плейлист играет сразу, текстовый
  запрос показывает 5 результатов с выбором. **Spotify-ссылки на треки** тоже
  работают (название через oEmbed → поиск на YouTube, ключи не нужны);
  плейлисты Spotify — задел под API (`SPOTIFY_CLIENT_ID/SECRET`).
- `/playnext <ссылка или запрос>` — то же, но трек встаёт первым в очереди.
- Сообщение-плеер с кнопками: ⏮️ назад · ⏯️ пауза/играть · ⏭️ следующий ·
  🔁 повтор (выкл/трек/все) · ⏹️ стоп · 🔉/🔊 громкость · 🔀 перемешать ·
  📜 караоке (текст подгружается в кэш при старте трека — включается мгновенно;
  повторное нажатие выключает; если синхронного текста нет — покажет обычный).
- Живой прогресс трека (полоса + `1:23 / 3:45`) через редактирование сообщения.
- `/queue`, `/skip`, `/shuffle`, `/stop`, `/pause`, `/resume`,
  `/volume 0–200`, `/nowplaying`, `/leave`.
- `/lyrics` — текст текущего трека (lrclib.net, включая японскую и русскую музыку);
  `/lyrics live:true` — караоке-режим: текст абзацами синхронно с воспроизведением
  (сообщение обновляется при смене абзаца, следующий абзац показан приглушённо).
- **Плейлисты сервера**: `/playlist save|play|list|delete` — сохранение текущей
  очереди в БД (лимиты `MUSIC_PLAYLIST_MAX_PER_GUILD`/`MAX_TRACKS`); удаляет
  автор или админ.
- **Кэш аудио против заиканий**: следующие `MUSIC_PREFETCH_TRACKS` (3) трека
  очереди фоном скачиваются на диск (`MUSIC_CACHE_DIR`, LRU-лимит
  `MUSIC_CACHE_MAX_MB` МБ) и играют из файла — сеть не влияет на звук.
  Первый трек стартует мгновенно стримом; если скачать не удалось — стрим
  как фолбэк. Live-эфиры всегда стримятся. `MUSIC_PREFETCH_TRACKS=0` — выкл.
- Авто-выход: когда очередь кончилась, плеер сразу удаляется; за
  `MUSIC_IDLE_WARN_SECONDS` (2 мин) до выхода Попося спрашивает «включить
  что-то ещё?», и если ответа нет — уходит через `MUSIC_IDLE_TIMEOUT` (5 мин)
  после конца музыки. Новый трек всегда создаёт свежий плеер внизу канала.
  Также выходит сразу, когда все покинули канал.
- Кнопки работают только для тех, кто в голосовом канале с ботом.

## Каморки: временные голосовые каналы

Зашёл в канал-хаб — Попося создаёт личную «каморку» и переносит туда. Вышел
последний человек — канал исчезает вместе со всей перепиской. Команд у модуля
нет вообще: всё делается кнопками.

**Включение** (админ): `/config channel key:tempvoice_hub_channel channel:#хаб`.
Хаб — он же выключатель: не задан, значит модуль молчит.

**Панель** из восьми кнопок лежит в двух местах и переживает рестарт бота:

- постоянная **витрина в чате хаба** — действует на ту каморку, где ты сейчас
  сидишь, состояние показывает лично тебе (сообщение одно на всех, поэтому
  чужую дверь в нём не покажешь);
- личная **панель в чате самой каморки** — там же видно её состояние: дверь,
  видимость, мест, хозяин. Discord открывает этот чат сам, когда заходишь в
  канал, так что панель попадается на глаза без единого клика.

| Кнопка | Что делает |
|---|---|
| 🔒 **Замок** | Закрыть/открыть дверь для всех |
| 🙈 **Скрыть** | Убрать/вернуть канал из списка |
| ✏️ **Имя** | Переименовать (Discord разрешает 2 раза за 10 минут — на третий Попося честно скажет, сколько ждать) |
| 🔢 **Мест** | Лимит 0–99; 0 = без лимита |
| 👢 **Выгнать** | Выставить из канала (пикер участника) |
| ✅ **Впустить** | Пускать конкретного человека даже в закрытую |
| ⛔ **Забанить** | Закрыть дверь и выставить, если уже внутри |
| 👑 **Забрать** | Единственная кнопка не для владельца: хозяин ушёл, а ты внутри — каморка твоя. При живом хозяине не сработает |

Всё, кроме «Забрать», доступно только владельцу. Блок-листы отдельно не
хранятся — это обычные права канала Discord, поэтому исчезают вместе с ним.

Время в каморках идёт в очки отношений наравне с любым другим войсом.
Осиротевшие каморки (пустые или удалённые руками, пока бот лежал) убираются при
старте — реестр каналов в БД.

| Настройка `/config` | Что делает |
|---|---|
| `tempvoice_hub_channel` | Канал-хаб; 0 = модуль выключен |
| `tempvoice_category` | Категория для каморок; 0 = категория хаба |
| `tempvoice_max_per_guild` | Потолок каморок, 1–50 (у Discord жёсткий лимит: 50 каналов в категории) |
| `tempvoice_default_limit` | Мест в новой каморке, 0–99; 0 = без лимита |

Боту нужны **Manage Channels** (создавать и удалять) и **Move Members**
(перенести в каморку) — без второго человек останется сидеть в хабе.

## Требования

- Python 3.11+
- **FFmpeg** в PATH (Windows: `winget install Gyan.FFmpeg`, затем перезапустить терминал;
  либо укажите путь в `FFMPEG_PATH` в `.env`)
- Токен бота: [Discord Developer Portal](https://discord.com/developers/applications) →
  New Application → Bot → Reset Token. Включите оба привилегированных интента:
  Message Content и Server Members.

Пригласительная ссылка (подставьте CLIENT_ID приложения):

```
https://discord.com/oauth2/authorize?client_id=CLIENT_ID&scope=bot%20applications.commands&permissions=1099833617430
```

(права: Send Messages, Embed Links, Connect, Speak, Manage Roles, Timeout Members, Ban/Kick Members, Manage Messages, Manage Channels, Move Members)

## Установка через Docker — пошаговая инструкция

Подходит тем, кто ничего не знает о Python: всё нужное (Python, FFmpeg, opus)
уже внутри образа. Нужен только Docker.

### Шаг 1. Установите Docker Desktop

1. Скачайте с https://www.docker.com/products/docker-desktop/ и установите.
   На Windows при установке согласитесь на включение **WSL 2** и перезагрузите ПК.
2. Запустите Docker Desktop и дождитесь статуса «Engine running».
3. Проверка в терминале: `docker --version` — должна показаться версия.

### Шаг 2. Создайте бота в Discord

1. https://discord.com/developers/applications → **New Application** → имя (например, Poposya).
2. Вкладка **Bot** → **Reset Token** → скопируйте токен (никому не показывайте).
3. Там же включите **Message Content Intent** и **Server Members Intent**
   (Privileged Gateway Intents) — оба обязательны.
4. Вкладка **OAuth2** → скопируйте **Client ID** и пригласите бота на сервер ссылкой
   (подставьте свой CLIENT_ID):
   `https://discord.com/oauth2/authorize?client_id=CLIENT_ID&scope=bot%20applications.commands&permissions=1099833617430`
5. На сервере поднимите роль бота **выше** будущих ролей-статусов
   (Настройки сервера → Роли → перетащите роль бота вверх).

### Шаг 3. Получите ключ Groq (бесплатно)

https://console.groq.com/keys → **Create API Key** → скопируйте ключ.

### Шаг 4. Настройте проект

В папке проекта скопируйте `.env.example` в файл с именем `.env` и заполните:

```dotenv
DISCORD_TOKEN=токен_из_шага_2
GROQ_API_KEY=ключ_из_шага_3
DEV_GUILD_ID=id_вашего_сервера          # чтобы команды появились сразу
```

(путь к базе для контейнера подставляется автоматически в docker-compose.yml —
править `DATABASE_URL` не нужно)

(ID сервера: в Discord включите «Режим разработчика» в настройках → ПКМ по серверу → «Копировать ID».)

### Шаг 5. Запустите

В терминале, в папке проекта:

```powershell
docker compose up -d --build
```

Первая сборка занимает несколько минут. Проверки:

- `docker compose ps` — у сервиса `bot` статус должен стать **healthy** (после ~минуты);
- http://localhost:8080/health в браузере — `{"status": "healthy", ...}`;
- логи: `docker compose logs -f bot`;
- в Discord появились команды `/play`, `/rank` и бот отвечает на упоминание.

### Управление

| Действие | Команда |
|---|---|
| Остановить | `docker compose down` (база сохраняется на volume) |
| Перезапустить | `docker compose restart bot` |
| Обновить после изменения кода/настроек | `docker compose up -d --build` |
| Логи | `docker compose logs -f bot` |

### Если музыка не играет (ошибка про «Sign in to confirm»)

YouTube требует cookies (см. раздел выше). Для Docker: экспортируйте `cookies.txt`
расширением браузера, положите файл рядом с `docker-compose.yml`, раскомментируйте
строку `./cookies.txt:...` в compose-файле и добавьте в `.env`:
`YTDLP_COOKIES_FILE=/app/data/cookies.txt`. Вариант `YTDLP_COOKIES_FROM_BROWSER`
в контейнере не работает — браузера там нет.

### Health-эндпоинты

Бот поднимает HTTP-сервер на порту 8080 (настройка `HEALTH_PORT`): `/health` и
`/ready` возвращают состояние проверок `database` и `discord` (200 — всё живо,
503 — что-то упало). Docker сам перезапустит контейнер по healthcheck из compose.

### Если YouTube пишет «Sign in to confirm you're not a bot»

YouTube помечает некоторые IP и требует авторизацию — без cookies поток не отдаётся
(поиск при этом работает). Решение:

1. Установите в браузер расширение **Get cookies.txt LOCALLY**.
2. Зайдите на youtube.com под своим аккаунтом и экспортируйте cookies в файл.
3. В `.env` укажите: `YTDLP_COOKIES_FILE=C:/путь/к/cookies.txt`.

Вариант `YTDLP_COOKIES_FROM_BROWSER=chrome` работает только когда Chrome закрыт
(база cookies залочена запущенным браузером), поэтому файл надёжнее.

Тесты application-слоя не требуют ни Discord, ни сети — плеер тестируется
через фейковые порты (`IVoiceConnection`, `IAudioSource`).

## Структура

```
src/
├── domain/            # сущности, доменные события, интерфейс шины — без фреймворков
│   ├── events/        # DomainEvent / CriticalDomainEvent, IEventBus
│   └── music/         # Track, RepeatMode, TrackStarted, исключения
├── application/       # логика фич и порты
│   ├── interfaces/    # IAudioSource, IVoiceConnection
│   ├── music/         # GuildPlayer (очередь, повтор, тайминг), DI фичи
│   └── di/            # root_container — composition root
├── infrastructure/    # реализации портов
│   ├── audio/         # yt-dlp
│   ├── discord/       # клиент, голосовой адаптер, коги
│   │   └── cogs/music/  # тонкий ког + сервисы: session (состояние гильдии),
│   │                    # service (плеер/сообщение/idle), lyrics (караоке),
│   │                    # radio, views (persistent-кнопки), formatting
│   ├── events/        # InMemoryEventBus (изоляция ошибок подписчиков)
│   └── logging/       # JSON-логи, correlation_id (contextvars)
├── config.py          # Settings (pydantic-settings, .env)
└── main.py            # точка входа
```

Новая фича добавляется по алгоритму раздела 14 ТЗ: своя подпапка в
`domain/`, `application/`, свой ког — существующие фичи не правятся,
связь только через события `IEventBus`.
