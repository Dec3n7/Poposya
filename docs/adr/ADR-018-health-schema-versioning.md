# ADR-018 — Версионирование health-схемы бот↔WARDEN и contract-тесты

- **Статус:** Accepted (2026-10-21)
- **Связано:** [ADR-004](ADR-004-warden-independent.md) (граница Poposya↔WARDEN), [ADR-013](ADR-013-warden-docker-socket-allowlist.md); план — [Poposya_improvement_plan §15](../plans/Poposya_improvement_plan.md)

## Контекст

WARDEN наблюдает бота снаружи по HTTP и **не импортирует код приложения**
(ADR-004). Единственная связь — health-контракт: `/health/full` (и `/api/health`
у панели). Изменение формата `/health/full` не должно молча ломать автономное
лечение — ADR-004 прямо помечал «версионирование health-схемы пока неявное» как
открытый риск; план §15 усиливался «ync contract tests против формата Poposya
health endpoint».

Факт на момент решения: `/health/full` (`infrastructure/web/app.py:99-129`)
возвращает `{status, checks, metrics, uptime_seconds, collect_duration_ms,
collected_at}` — **без поля версии**. Тестов, фиксирующих этот формат как
контракт, нет: есть только unit-тесты `HealthChecker`
(`tests/test_health*.py`), но не проверка состава и типов полей ответа. То есть
изменение ключа или смысла поля обнаружится только когда WARDEN уже принял
решение по сломанным данным.

## Решение

**Health-схема бота версионируется явно, а её форма закреплена contract-тестами
со стороны бота.**

- `/health/full` (и `/api/health`, где отдаёт структурированные данные)
  включают поле `health_schema_version` — целое, монотонно растущее при любом
  обратно-несовместимом изменении состава/типов/смысла полей (`checks`,
  `metrics`, `status`, `uptime_seconds`, `collect_duration_ms`, `collected_at`).
  Текущее значение — `1`.
- **Версия ставится только в борющемся поле ответа**, а не в заголовок: тело уже
  читается WARDEN целиком, и версия обязана приходить даже когда ворота закрыты
  (эндпоинт всегда 200 — app.py:102-104).
- Обратно-совместимые добавления (новое поле метрики, новый ключ в `checks`)
  версию **не** поднимают: WARDEN читает по именам и игнорирует неизвестное.
- **Contract-тест на стороне бота** фиксирует: присутствие обязательных полей,
  их типы, `health_schema_version == EXPECTED`, и что `checks`/`metrics` —
  словари, а `status` — одно из `{healthy, unhealthy}`. Тест падает при
  изменении схемы и заставляет автора либо поднять версию, либо подтвердить
  обратную совместимость.
- WARDEN-сторона (вне этого репозитория) сверяет пришедшую версию с последней
  известной ей и деградирует предсказуемо (лог + консервативный режим), а не
  падает. Деталь сверки — предмет репозитория WARDEN, здесь фиксируется
  обязательство бота **всегда сообщать версию**.

## Последствия

- **Плюсы:** смена формата из «молчаливой» становится «объявленной»; contract-тест
  в CI ловит несовместимость до деплоя; WARDEN может распознать старую/новую
  схему. Закрывает открытый риск ADR-004.
- **Минусы / цена:** обязательство поддерживать поле версии и обновлять
  `EXPECTED` в тесте при каждом ломающем изменении — небольшая дисциплина.
- **Риски / что осталось открытым:**
  - Сверка версии внутри WARDEN — отдельная работа и отдельный репозиторий; этот
    ADR задаёт контракт только со стороны бота.
  - Обратная совместимость опирается на «WARDEN читает по именам»: если WARDEN
    начнёт требовать строгий состав, добавление поля потребует мажорного шага —
    это уже решения WARDEN.
  - `/api/health` панели сейчас минимален (`{"status": "ok"}`); версия для него
    вводится только если/когда он станет источником структурированных данных для
    WARDEN, а не останется liveness-пробой.
