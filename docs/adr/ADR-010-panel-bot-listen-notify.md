# ADR-010 — Интеграция панель↔бот через Postgres `LISTEN/NOTIFY`

- **Статус:** Accepted (2026-07-18)
- **Связано:** [ADR-001](ADR-001-postgresql-production-database.md), [ADR-008](ADR-008-per-guild-settings-provider.md), [ADR-011](ADR-011-durable-command-bridge.md), план-первоисточник — [CONCURRENCY_PLAN «Фикс #2»](../plans/CONCURRENCY_PLAN.md)

## Контекст

Веб-панель ([ADR-012](ADR-012-web-panel-reuses-domain.md)) — второй процесс,
пишущий в ту же БД. Бот держит настройки/персоны/тарифы в **кэше в памяти** ради
горячего пути чтения. Если панель пишет изменение прямо в БД, бот об этом не
узнает до рестарта — это не гонка строк, а межпроцессная **инвалидация кэша**.
Нужен способ сказать боту «перечитай гильдию X», не добавляя новую инфраструктуру.

## Решение

Синхронизация состояния между панелью и ботом — через **Postgres `LISTEN/NOTIFY`**
(Redis не понадобился).

- Писатель (панель или бот) шлёт `pg_notify(<канал>, guild_id)` в **той же
  транзакции**, что и запись (доставка на COMMIT, откат на rollback; payload —
  bind-параметр, без инъекций). Каналы: `poposya_settings`, персоны,
  `poposya_entitlements`.
- Слушатель (`SettingsChangeListener`, `EntitlementChangeListener`) держит
  отдельное asyncpg-соединение, `LISTEN` канала и по уведомлению зовёт
  `reload_guild(guild_id)`. На каждом (пере)подключении — полный `load_all`
  (пропущенные за простой NOTIFY не буферизуются Postgres).
- На SQLite фабрика листенера возвращает `None` (второго писателя нет) — код
  остаётся диалект-нейтральным ([ADR-001](ADR-001-postgresql-production-database.md)).

Тот же транспорт переиспользован для командного моста
([ADR-011](ADR-011-durable-command-bridge.md)) — отдельный inbound-механизм не нужен.

## Последствия

- **Плюсы:** оператор выдал Premium / поменял настройку — эффект без рестарта
  бота; ноль новой инфраструктуры; транзакционная доставка (не разъезжается с
  записью).
- **Минусы / цена:** `LISTEN/NOTIFY` — «в лучшем случае одна доставка», поэтому
  на (пере)подключении обязателен полный `load_all`; лишнее соединение на слушателя.
- **Риски / что осталось открытым:** только Postgres (в проде это и есть БД —
  [ADR-001](ADR-001-postgresql-production-database.md)); при росте числа каналов
  стоит следить за их именованием и полезной нагрузкой.
