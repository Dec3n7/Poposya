# ADR-015 — Новости игр Riot: независимая вертикаль `/riot` через общий `__NEXT_DATA__`

- **Статус:** Accepted (2026-10-21), расширено 2026-10-21 (семейство Riot)
- **Связано:** [ADR-006](ADR-006-feature-oriented-architecture.md) (вертикали на фичи), [ADR-007](ADR-007-hexagonal-dependency-rule.md); прецеденты — вертикали `steam` и `git`

## Контекст

Трекеров новостей сейчас два: Steam (`/steam add`) и GitHub (`/git add`) — каждый
со своей вертикалью, своим поллингом и своим хранилищем. Запрос — добавить
новости игр **Riot Games**: сначала Valorant, затем и остальных.

Valorant нельзя поймать существующим Steam-путём, и прямых замен нет:

1. **Игра не в Steam.** `/steam add` принимает только числовой AppID или
   `store.steampowered.com/app/<id>` (`domain/steam/refs.py:12-21`) и валидирует
   игру через storefront `appdetails` (`cogs/steam.py:227-234`) — для Valorant
   ответ `success:false`, команда отклоняет.
2. **Новости — из Steam-фида.** `ISteamNews/GetNewsForApp` по appid с фильтром
   `feedname == "steam_community_announcements"` (`application/steam/dto.py:36-43`);
   у Riot-игр такого фида нет.
3. **У Riot нет публичного новостного API и RSS.** Проверено 2026-10-20:
   `playvalorant.com/{locale}/news/` — SSG на Next.js; в HTML встроен
   `<script id="__NEXT_DATA__">` с полноценной лентой хедлайнов: `title`,
   `description` (HTML), `action` (`weblink` | `youtube_video` с `payload.url`),
   `category`, `publishedAt`, `analytics.contentId` (стабильный UUID),
   `media.url`. Это обычный GET без ключей и аутентификации.
4. **Та же схема у остальных сайтов Riot** (проверено 2026-10-20):
   `leagueoflegends.com`, `teamfighttactics.leagueoflegends.com`,
   `wildrift.leagueoflegends.com`, `2xko.riotgames.com` — тот же blade
   `fragmentId == "news"`. Исключение — `playruneterra.com`: клиентский SPA без
   `__NEXT_DATA__`, в общую схему не укладывается и намеренно не поддерживается.
   Отличия боевого формата от первоначальной фикстуры: `category` и
   `description` приходят объектами (`{title, machineName}`, `{type, body}`), а
   `action.payload.url` у внутренних новостей — относительный путь; `page.baseUrl`
   в `__NEXT_DATA__` даёт базу для его достройки.


Проект сознательно дважды выбирал паттерн «вертикаль на источник» вместо
общего движка (steam и git — независимые вертикали, общий только стиль).
Вопрос решения: продолжить этот паттерн или впервые унифицировать трекеры.

## Решение

### 1. Riot — новая независимая вертикаль `riot`, steam не трогается

Строится **`src/domain/riot/` → `src/application/riot/` →
`src/infrastructure/riot/`** по правилам ADR-007, по образцу существующих
вертикалей steam и git. Вертикаль `steam` **не рефакторится вообще** — ни
порты, ни схема, ни UX: работающий, протестированный трекер остаётся как есть.

Дублируется специфика источника (baseline при добавлении, маркер-дедупликация,
«отметка после успешной публикации», эмбед) — в объёме, который проект уже
дважды принял как цену паттерна. Самая рискованная механическая часть — цикл
поллинга (старт на `on_ready`, интервал, изоляция исключений, остановка) —
**не дублируется**: выносится в минимальный общий хелпер
`application/news/poller.py`. Это не порт источников и не обобщение движка:
хелпер владеет только таймером, вызов use-case остаётся в вертикали. Steam на
хелпер в рамках этого решения **не переезжает** (обещанный нулевой риск);
миграция steam — отдельный малый follow-up. Хранение — своя таблица, своя
репа-вертикаль.

### 2. Источник Riot — `__NEXT_DATA__`, не скрейп DOM

`infrastructure/riot/client.py`: GET `<сайт игры>/{locale}/news/`
→ извлечение `__NEXT_DATA__` → blade с `fragmentId == "news"` → `items` →
доменные `RiotNewsItem` (заголовок, дата, ссылка из `action.payload.url`,
первая картинка из `media`/`imageMedia`, описание — конвертированный HTML в
Discord-markdown). Один разбор обслуживает все игры: схема лент у них общая,
а поддержаны обе формы полей (`category`/`description` — объект или строка) и
достройка относительного `action.payload.url` по `page.baseUrl`.

- **Идентификатор записи — цепочка фолбэков:** `analytics.contentId` →
  `action.payload.url` → детерминированный хеш `title+publishedAt`. Схема
  blade-блока не валидируется, поля могут отсутствовать у части items (старые
  записи, видео) — поэтому ошибки **изолируются на уровне item**: неразобранный
  item пропускается с warning-логом, лента живёт дальше. Fail-soft на весь фид
  срабатывает только если не распарсен **ни один** item или отсутствует сам
  blade.
- **Маркер дедупликации:** пара `(last_news_date, last_news_gid)`, куда
  разрешённый по цепочке id кладётся строкой — схема мышления как у Steam.
- **Локаль:** настройка `riot_locale` (дефолт `ru-ru`) плюс **per-game дефолт**
  в домене (`ru-ru` для Valorant/LoL/TFT/Wild Rift, `en-us` для 2XKO — русского
  у последней нет). Серверная настройка нормализуется и используется, если
  задана; пустая — откатывается на дефолт игры (`resolve_locale`). Так одна
  команда обслуживает игры с разными наборами локалей без новых настроек.
- **Fail-soft обязан быть наблюдаемым:** счётчик подряд неудачных тактов
  фетча; после порога — warning-лог и метрика (забирается существующей
  инфраструктурой логов/health), чтобы «тишина» при geo/контрактных отказах
  была заметна оператору, а не вечной и молчаливой.
- **Рендер различает тип item:** `action.type == youtube_video` — превью и
  явное поле «Видео» (ссылка на YouTube) в эмбеде; `weblink` — баннер статьи.
  Иначе новость-видео выглядит как обычная статья.
- **Baseline:** при `/riot add` в тред сразу публикуется свежайшая
  новость, дальше — только маркерные.

Отклонённые альтернативы источника:

- **Прямой Sanity query API** (CMS сайта) — приватный projectId/dataset,
  контракт не публичный; при этом публичный HTML уже содержит всю ленту.
- **DOM-скрейп** — тяжелее и хрупче, чем JSON в SSG-блобе.
- **YouTube-ретрансляция Riot** — другой тип контента, не новости.
- **Внешний агрегатор-посредник** — лишняя зависимость против независимости
  (дух ADR-004).

Отклонено и **обобщение до общего движка** (порт `INewsSource`, единый
`PollNewsUseCase`, рефакторинг steam в адаптер): это снимало бы будущее
дублирование, но покупалось бы самым рискованным изменением рабочего
трекера ради экономии ~300 строк при двух-трёх источниках навсегда.
Решение — за стабильностью и независимостью вертикалей.

### 3. Схема БД: своя таблица `riot_tracked_games`

По образцу `tracked_games` (миграция 0033, `db/models/steam.py`):

- `id PK`, `guild_id`, `game TEXT NOT NULL` (значения: `valorant`, `lol`,
  `tft`, `wildrift`, `2xko`), `thread_id`,
  `last_news_gid` (contentId), `last_news_date`, `added_by`, `created_at`;
- `UNIQUE(guild_id, game)`, `INDEX(guild_id)`.

Своя репа-вертикаль `db/repositories/riot.py`, свой порт в
`domain/riot/repository.py`, подключение в `unit_of_work.py`.

### 4. Команды, канал и гейтинг: пространство `/riot`

- **Команда: `/riot add|remove|list`** — cog `infrastructure/discord/cogs/riot.py`
  по образцу `steam.py` (дубль-проверка, карточка при добавлении, обязательный
  форум-канал), регистрация в `infrastructure/discord/client.py`. Опция
  `game` — choices по всем играм семьи (дефолт `valorant`); новая игра
  добавляется значением в домене `RiotGame` + URL сайта, без новой команды и
  без новых настроек.
- **Посты — треды в форум-канале** (как у Steam и GitHub): на сервере заводится
  отдельный форум-канал (например, «Новости Riot»), одна игра = один тред,
  внутри — посты новостей. Канал обязателен: без него `/riot add` отвечает
  с подсказкой на настройку.
- **Настройка канала — и в Discord, и в панели, из одного ключа:**
  `riot_forum_channel` (`int`, 0 = выкл) — обычная channel-ключаевая настройка в
  `application/guild_config/schema.py` (по образцу `steam_forum_channel:161`),
  плюс `riot_locale`. Она автоматически доступна в обоих местах: команда
  `/config channel key:riot_forum_channel` и вкладка «Настройки» веб-панели
  (schema-driven рендер + группа «Riot-игры» по префиксу `riot_` в
  `web/src/components/GuildSettings.tsx:32`) — отдельный API и код панели не
  нужны.
- **Схема мышления — «канал/локаль/модуль общие, трекинг per-game».** Оси
  разведены явно: `riot_enabled`, `riot_forum_channel`, `riot_locale` —
  общие на семью Riot; трекинг — отдельная запись на игру (`/riot add game:`,
  `UNIQUE(guild_id, game)`). Включение следующей игры = модуль и канал уже
  заданы + один `/riot add game:lol`, не три новых настройки.
- **Гейтинг:** модуль-ключ `riot_enabled` (`PlanTier.PREMIUM`, как
  `steam_enabled` в `application/guild_config/schema.py:352`). Сервер может
  включить Steam-трекер, Riot-трекер или оба независимо; внутри `riot_enabled`
  каждая игра всё равно требует своего канала и явного `/riot add`.
- **Гонки и дубли:** дубль-проверка — до записи (в cog); одновременные два
  `add` одной игры ловятся `UNIQUE(guild_id, game)` → IntegrityError
  обрабатывается дружелюбным ответом («уже отслеживается»), не 500 — на это
  пишется тест.

### 5. Порядок внедрения (по слоям)

1. Домен и приложение: `domain/riot/` (сущности, порт репозитория),
   `application/riot/` (use-cases add/remove/list/poll, DI-контейнер),
   общий хелпер `application/news/poller.py` (механика таймера поллинга).
2. Схема: миграция `riot_tracked_games`, `db/models/riot.py`,
   `db/repositories/riot.py`, `unit_of_work.py`.
3. Источник: `infrastructure/riot/client.py` (fetch + парсер `__NEXT_DATA__`;
   фикстура — снапшот реального ответа) + HTML→markdown конвертер
   (подмножество: параграфы, bold/italic, ссылки, списки — в
   `infrastructure/riot/`).
4. Discord: cog `riot.py`, поллинг-цикл по образцу steam, эмбед-рендер,
   регистрация в `discord/client.py`.
5. Конфиг и гейтинг: `riot_enabled`, `riot_forum_channel`, `riot_locale`
   (сразу видны в `/config` и во вкладке «Настройки» панели), `ModuleSpec`
   в `guild_settings.py`, сборка в `root_container.py`.
6. Тесты по образцу steam + специфика контракта: **contract-тесты парсера на
   снапшотах реальных `__NEXT_DATA__`** каждой игры (фикстуры с версией/датой
   в имени, напр. `lol_news_ru-ru_2026-10-20.json`, `2xko_news_en-us_2026-10-20.json`)
   — снапшот и есть контракт, его обновление при апгрейдах сайта/Next.js —
   явная часть релиз-чек-листа; тест достройки относительного URL по
   `page.baseUrl`; тест изоляции неразобранного item (остальные проходят); poll
   через фейковый клиент (в т.ч. несколько игр одного сервера); use-cases;
   ког-фейки; гонка двойного `/riot add` (IntegrityError → дружелюбный ответ).

## Последствия

- **Плюсы:** нулевой регрессионный риск для Steam и GitHub — их код не
  трогается вовсе; вертикаль удаляется/релизится/ревертится атомарно;
  консистентно с дважды принятым паттерном «вертикаль на источник»
  (ADR-006/007); Valorant без API-ключей и без хрупкого DOM-скрейпа;
  каждый сервер сам включает нужные трекеры.
- **Минусы / цена:** дублируется специфика источника — baseline, маркеры,
  посты, эмбед (~200 строк вместо ~300: поллинг-цикл вынесен в общий хелпер) —
  баги этой специфики чинятся в двух местах (steam, riot); своя таблица/репа
  вместо общей; почти-идентичный код steam и riot разъезжается при эволюции
  обоих.
- **Риски / что осталось открытым:**
  - контракт `__NEXT_DATA__` — публичный, но не вечный: мажорный апгрейд
    Next.js/сайта может изменить формат blade-блока; страхует fail-soft
    (изоляция на уровне item), а мажорные изменения ловит **contract-тест на
    версионированном снапшоте** — обновление снапшота есть часть релиза, а не
    рутинный фикс;
  - лента хедлайнов ограничена последними N записями (полного архива нет) —
    для новостного трекера с поллингом 2 ч достаточно;
  - Cloudflare/geo-блокировки на `playvalorant.com` — отслеживать первые
    недели; постоянный geo-отказ для хостинга бота не будет молчаливой
    вечностью: счётчик подряд неудачных тактов шлёт warning/метрику (§2),
    оператор увидит «тишину»;
  - **условие пересмотра:** семейство Riot (5 игр) уложилось в одну вертикаль
    и один парсер — обобщение до общего движка не потребовалось. Если
    появится источник **вне семейства Riot** (другая схема лент) или
    дублирование начнёт расходиться болезненно — завести ADR на обобщение
    (порт источника, общие посты/маркеры; поллинг-хелпер уже общий),
    мигрировать riot первым.
  - Runeterra (`playruneterra.com`) не поддержан: клиентский SPA без
    `__NEXT_DATA__`. При необходимости — отдельный источник, не ломающий общий
    разбор.
