# ADR-016 — Единый `NewsPoller` для новостных трекеров

- **Статус:** Accepted (2026-10-21)
- **Связано:** [ADR-015](ADR-015-news-sources-valorant.md) (завёл общий хелпер для Riot), [ADR-006](ADR-006-feature-oriented-architecture.md) (вертикали на фичи), [ADR-007](ADR-007-hexagonal-dependency-rule.md)

## Контекст

Новостных трекеров три: Steam (`/steam`), GitHub (`/git`) и Riot (`/riot`). Каждый
— независимая вертикаль со своим use-case опроса. ADR-015 вынес самую
механическую, дублируемую часть — таймер поллинга — в минимальный общий хелпер
`application/news/poller.py` (`NewsPoller`) и явно записал: «Steam на хелпер в
рамках этого решения не переезжает; миграция steam — отдельный малый follow-up».

Факт на момент решения: `cogs/steam.py:78-95` и `cogs/git.py:91-108` держат
собственные циклы опроса (`on_ready` + гвард `_loop_started` + `_poll_loop` +
список `_tasks` + отмена в `cog_unload`). Логика этих циклов **поведенчески
идентична** `NewsPoller`: спит до первого такта, изолирует исключение такта
через `try/except Exception: logger.exception`, останавливается отменой задачи.
Отличий в бизнес-логике опроса нет — `git` лишь дополнительно ограничивает
бюджет API в самом `_run_poll`, что к таймеру не относится.

То есть дублируется ровно та механика, которую уже инкапсулировал `NewsPoller`;
три почти-идентичные копии цикла разъезжаются при эволюции.

## Решение

**Все новостные трекеры используют единый `NewsPoller`
(`application/news/poller.py`); локальные циклы опроса в когах удаляются.**

- Ког владеет одним `self._poller = NewsPoller(name=..., interval_seconds=...,
  tick=...)` (образец — `cogs/riot.py:57-61`).
- `on_ready` стартует поллер идемпотентно (`if self._poller.started: return`).
- `cog_unload` вызывает `self._poller.stop()`.
- Интервал остаётся прежним: `max(60, <настройка>_poll_interval_minutes * 60)`.
- Изоляция исключений такта и «сон до первого такта» — поведение `NewsPoller`,
  менять его не требуется.
- Специфика вертикали (что именно опросить, как отобрать новости, как
  отправить) остаётся в use-case и коге — `NewsPoller` владеет **только
  таймером**. Это не движок источников и не порт `INewsSource`: движки не
  обобщаются (см. ADR-006/015).

Область: `cogs/steam.py`, `cogs/git.py` (и, при появлении, любой следующий
новостной трекер). Riot уже на `NewsPoller`.

## Последствия

- **Плюсы:** одна реализация таймера вместо трёх; фикс поведения (например,
  «не стартовать дважды», именованные задачи) действует сразу во всех трекерах;
  меньше кода в когах; единообразные логи старта цикла.
- **Минусы / цена:** правка рабочего, протестированного Steam/Git-кода —
  регрессионный риск не нулевой, а поведение нужно сохранить один-в-один
  (интервал, «сон до такта», изоляция). Оправдано: эквивалентность поведения
  проверяема тестами.
- **Риски / что осталось открытым:**
  - `git` держит бюджет API в `_run_poll` — он переезжает без изменений, но
    тестами нужно подтвердить, что бюджет не завязан на поле задачи.
  - `NewsPoller` хранит одну задачу, а не список; если какому-то трекеру
    понадобятся несколько независимых циклов — это отдельное решение, а не
    молчаливое расширение хелпера.
  - миграция `git` делается тем же заходом; если её специфика окажется сложнее
    ожидаемой — допускается перенести `git` отдельным малым шагом, Steam
    мигрирует безусловно.
