# ADR-014 — Выдача тарифа сейчас (оператор/ключи), платёжка — идемпотентным webhook позже

- **Статус:** Accepted (2026-08)
- **Связано:** [ADR-009](ADR-009-tier-enforcement-seam.md), [ADR-010](ADR-010-panel-bot-listen-notify.md), первоисточники — [monetization-prep §6](../plans/monetization-prep.md), [premium-keys](../plans/premium-keys.md), [Technical_Audit_v2 §25–29](../plans/Poposya_WARDEN_Technical_Audit_v2.md)

## Контекст

Тарифы уже enforce'ятся ([ADR-009](ADR-009-tier-enforcement-seam.md)), но нужно
решить, **как тариф попадает в БД**. Давать платёжному провайдеру прямой контроль
над Discord-фичами опасно; вебхуки приходят 0..N раз (ретраи, таймауты); регион
(РФ) и выбор провайдера — продуктовое, ещё не финализированное решение. При этом
хочется начать выдавать подписки уже сейчас, не дожидаясь биллинга.

## Решение

Между «оплатой» и фичами всегда стоит **`EntitlementService` + таблица
`guild_entitlements`** — единственная точка, меняющая тариф. Способы выдачи
подключаются к ней, а не к фичам напрямую:

```text
оператор (панель)  ─┐
ключи (premium_keys)├→ EntitlementService.grant → guild_entitlements → LISTEN/NOTIFY → бот
платёжка (webhook) ─┘        (позже)
```

- **Сейчас:** ручная выдача оператором через API `PUT /api/guilds/{id}/entitlement`
  (`require_operator`, аудит) + одноразовый триал (таблица `guild_trials`,
  атомарный `start_trial`, серверный `has_used_trial` — не доверяем UI).
- **Ключи:** provider-agnostic путь — самоподписанные HMAC-ключи фиксированных SKU
  (`premium_keys/`), редемпшн атомарно пишет грант; проверка офлайн, отзыв партии —
  ротацией секрета.
- **Позже (внешнее):** платёжный провайдер дёргает `grant` через webhook. Webhook
  обязан быть идемпотентным (`provider_event_id UNIQUE`: обработан → 200; нет →
  записать событие → выдать), плюс периодический reconciliation-джоб и grace-период
  на неудачную оплату (не ронять в Free мгновенно).

## Последствия

- **Плюсы:** фичи не зависят от способа оплаты; можно продавать уже сейчас
  (оператор/ключи) до интеграции биллинга; синхронизация с ботом бесплатна через
  [ADR-010](ADR-010-panel-bot-listen-notify.md).
- **Минусы / цена:** ручная выдача не масштабируется — это временная модель;
  ключи требуют бережного обращения с подписывающим секретом.
- **Риски / что осталось открытым:** сам платёжный webhook, `provider_event_id`,
  reconciliation и grace-политика ещё не реализованы (P1/P2 аудита §27–29).
