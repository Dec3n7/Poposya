# ADR-019 — Скрытые ачивки как класс и вторая волна через аддитивные хуки

- **Статус:** Accepted (2026-10-21)
- **Связано:** план-первоисточник — [../plans/achievements.md](../plans/achievements.md); [ADR-003](ADR-003-event-bus-outbox.md) (шина событий), [ADR-016](ADR-016-unified-news-poller.md)

## Контекст

Ачивки уже реализованы: домен `src/domain/achievements/` (чистые предикаты над
`UserStats`, `newly_unlocked` — `entities.py:65-74`), каталог из 19 записей
(`catalog.py`), use-case оценки и витрины, ког с подпиской на события шины
(`FindClaimed`, `RelationshipRoleChanged`, `ExclusiveTransferred` — `cogs/achievements.py:67-69`)
и рендером карточек. Тир уже есть как тип (`Tier` — `entities.py:17-21`).

План `achievements.md` описал вторую волну («🔌-набор»: кино, секретка, ДР,
каморки, дуэли, первый разговор) и открыл два вопроса, требующих решения до
кодирования:

- **Скрытые ачивки** — вводить как класс (не видны до анлока) или держать все
  видимыми списком «что можно получить» (`achievements.md:124-125`)?
- **Триггеры 🔌** — ачивки, которым нет существующего события, требуют
  аддитивного `bus.publish(...)` в чужой фиче (`achievements.md:117-118`).

Задача требует зафиксировать оба решения архитектурно: скрытость задевает
контракт витрины и модель `Achievement`, а 🔌-хуки — способ интеграции ачивок с
чужими вертикалями, не создавая обратных зависимостей.

## Решение

**Скрытые ачивки вводятся как класс с явным полем в модели; вторая волна
подключается аддитивными событиями шины, без импорта вертикалей в домен ачивок.**

1. **Скрытость — свойство каталога, первый класс.** `Achievement` получает
   булево поле (например `hidden: bool = False`, `entities.py:42-54`). Витрина
   (`GetAchievementsUseCase`) показывает скрытые записи **только после анлока**;
   до анлока они не раскрывают ни имени, ни условия. Домен-предикаты при этом
   не меняются: скрытость влияет на отображение, а не на логику открытия.
2. **`Tier` остаётся как есть** — словарь находок (common/uncommon/rare/
   legendary, `entities.py:17-21`). Отдельный словарь «бронза/серебро/золото» не
   вводится: приводит к двум несогласованным шкалам при нулевой пользе. Тиры
   используются и для видимых, и для скрытых.
3. **Вторая волна — только аддитивные события.** Каждая 🔌-ачивка получает один
   новый факт на шине (`bus.publish(...)`), который публикует **фича-владелец**
   (кино, секретка, ДР, tempvoice, `/dice`, первый разговор в AI-чате). Домен
   ачивок **не импортирует** коги чужих вертикалей; направление зависимости —
   «чужое событие → ачивка», как уже сделано для находок/отношений. Это следует
   Dependency Rule (ADR-007) и повторяет прецедент подписки кога.
4. **Оценка остаётся выводимой** — `newly_unlocked` не обрастает счётчиками:
   новый факт либо входит в `UserStats`, либо даёт отдельный предикат; бэкфилл
   остаётся бесплатным для всего, что выводимо из состояния.

Область реализации: `entities.py` (поле скрытости), `catalog.py` (записи второй
волны + метка hidden), `GetAchievementsUseCase` (фильтрация витрины),
`cogs/achievements.py` (новые подписки), плюс по одному `bus.publish(...)` в
когах-владельцах. Тиры и рендер — без новых механизмов.

## Последствия

- **Плюсы:** скрытые пасхалки получают явную поддержку, а не «все видны»; чужие
  вертикали не знают об ачивках — связь односторонняя через шину; ноль общих
  зависимостей; бэкфилл выводимого сохраняется.
- **Минусы / цена:** каждое 🔌-событие — правка чужого кога (по одному хуку на
  ачивку) и новый контракт события на шине; витрину нужно аккуратно фильтровать,
  чтобы скрытые не «протекали» в списке.
- **Риски / что осталось открытым:**
  - **Иконки** (`achievements.md:126-129`) — отдельный технический кусок
    (цветной эмодзи/Pillow `embedded_color=True` / PNG-ассеты); этот ADR его не
    решает, он остаётся открытым вопросом рендера.
  - **Бэкфилл** (`achievements.md:130-132`) — разовый проход или ленивая
    проверка при первом `/achievements`; механика не выбрана, ADR фиксирует
    лишь требование «выводимость сохраняется».
  - Мета-ачивка «Коллекционер ачивок» (`achievements.md:101`) зависит от числа
    открытых — это отдельный счётчик поверх состояния, решение по нему не здесь.
