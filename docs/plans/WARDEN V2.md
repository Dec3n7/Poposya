# WARDEN
### Design & Runtime Specification

> Autonomous Monitoring System

---

# Philosophy

WARDEN — независимый системный сервис, предназначенный для мониторинга,
диагностики и автоматического восстановления контейнеризированных приложений.

Главная цель — обеспечить стабильность работы сервиса с минимальным вмешательством человека.

WARDEN не является частью приложения.

Он работает как внешний Guardian.

---

# Design Principles

WARDEN придерживается следующих принципов.

## Minimal

Никакой лишней логики.

WARDEN не занимается:

- бизнес-логикой
- резервным копированием
- миграциями
- управлением данными

Он только наблюдает и реагирует.

---

## Predictable

Каждое действие заранее известно.

Observe

↓

Verify

↓

Restart

↓

Notify

Никаких бесконечных циклов восстановления.

---

## Independent

WARDEN не импортирует код приложения.

Допустимые способы взаимодействия:

- Docker API
- HTTP Health API
- Discord Webhook

# WARDEN Status

WARDEN имеет собственное состояние.

Оно не зависит от состояния приложения.

UNKNOWN

WARDEN не способен определить собственное состояние.

Используется только при старте или критической ошибке.

---

READY

Все компоненты работают.

Мониторинг активен.

Docker доступен.

API доступен.

---

DEGRADED

WARDEN функционирует частично.

Например:

- Discord недоступен
- Docker отвечает медленно
- Monitoring работает с ограничениями

---

FAILED

WARDEN не способен выполнять мониторинг.

Требуется вмешательство администратора.

---

# Target Health

Состояние приложения определяется отдельным Health Score.

100

↓

90

↓

78

↓

54

↓

31

Health Score никак не влияет на статус самого WARDEN.

---

# Recovery Policy

При каждом цикле выполняется:

Health Check

↓

Verify

↓

Decision

Если

Health Score > 50

никаких действий.

Если

Health Score ≤ 50

выполняется один Soft Restart.

После рестарта снова производится проверка.

Если Score всё ещё ≤50

никаких новых рестартов.

Создается Incident.

Отправляется уведомление.

WARDEN продолжает мониторинг.

# Visual Identity

WARDEN использует минималистичный интерфейс.

Основным визуальным элементом являются светящиеся кольца.

READY

Белое свечение.

DEGRADED

Синее свечение.

FAILED

Красное свечение.

UNKNOWN

Зеленое свечение.

Никаких сложных иконок.

Никаких иллюстраций.

Только статус.

---

# Logging Style

Каждое действие имеет единый формат.

[INFO]

[WARNING]

[ERROR]

[CRITICAL]

Пример

[INFO] Monitoring started

[INFO] Target READY

[WARNING] Health Score dropped to 49

[INFO] Soft Restart initiated

[INFO] Restart completed

[INFO] Monitoring resumed

---

# Design Goals

WARDEN должен выглядеть как профессиональный инфраструктурный сервис.

Не как Python-приложение.

Не как бот.

Не как Web Dashboard.

А как отдельная системная служба уровня:

• systemd
• Docker
• Kubernetes
• Prometheus

Каждый экран должен создавать ощущение надежности, минимализма и полного контроля над системой.
